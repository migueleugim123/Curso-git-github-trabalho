# Aprendizados finais

## O que foi aprendido

Durante o desenvolvimento deste projeto, foi possível praticar a criação de um guia didático em Markdown e a organização de arquivos em um repositório Git.

Também foram trabalhados conceitos de:

- criação e organização de arquivos Markdown;
- uso de branches;
- commits atômicos;
- pull requests;
- revisão de conteúdo;
- resolução de conflitos;
- visualização do histórico com `git log`;
- publicação do projeto no GitHub.

## Reflexão sobre Git e GitHub

O uso de branches ajudou a separar diferentes partes do trabalho e tornou o desenvolvimento mais organizado. Os commits com mensagens claras facilitam a identificação do que foi alterado em cada etapa.

O pull request também foi importante para simular um processo de revisão antes de integrar uma alteração à branch principal.

## Dificuldade encontrada

Uma das principais dificuldades foi compreender como um conflito de merge acontece quando duas versões alteram a mesma parte de um arquivo.

## Como a dificuldade foi resolvida

A solução foi comparar as duas versões, escolher o conteúdo mais adequado, remover os marcadores de conflito e testar o arquivo depois da resolução.

## Conclusão

O projeto mostrou que Git e GitHub não servem apenas para armazenar código. Eles também ajudam a organizar projetos, acompanhar alterações, colaborar e manter um histórico do desenvolvimento.
